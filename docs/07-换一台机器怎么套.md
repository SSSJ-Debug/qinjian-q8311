# 07 · 换一台机器怎么套

> 这份是"操作手册"——拿到一台陌生设备，照着走一遍就知道能不能搞。

---

## 阶段 0：十分钟能出结论的判断

```bash
# ① 设备是什么
ioreg -p IOUSB -w0 -l | grep -A12 "Android"     # macOS
lsusb | grep -E "05c6|0e8d|1782"                 # Linux

# ② 有没有 adb 窗口（关键：开机那几秒）
adb start-server
adb devices        # 空 = 需要蹲窗口，不空 = 直接跳过阶段 1
```

**判断**：

- 看到 `05c6:9020` 或 `adb devices` 有设备 → 直接跳到阶段 2
- 只看到 `05c6:9002` → 走阶段 1（蹲窗口）
- 什么都看不到 → 线/口/驱动问题，先解决这个

---

## 阶段 1：蹲窗口（8~14 秒）

### 1.1 先启动脚本，再开机

**顺序不能错。** 脚本必须在设备上电之前就跑起来。

```bash
./scripts/harvest.sh
# 然后在另一个窗口：拔 USB → 等 10 秒 → 插上（或按电源键）
```

### 1.2 盯日志

```bash
tail -f /tmp/adb_harvest.log
```

期望看到：

```
##### [10:24:31] WINDOW HIT #1: <serial> #####
  [weld 1] adb_enabled=[1]
  *** adb_enabled=1 焊接成功 ***
  *** tcpip 5555 已投递 ***
```

如果只有 `WINDOW HIT` 但焊接全失败（`adb_enabled=[0]` 或 `[]`）：
→ 窗口太短，AMS 没起来。改走**设备侧代理**（阶段 1.3）。

### 1.3 备选：设备侧代理

窗口内只做"送脚本进去 + 启动"：

```bash
adb push scripts/agent.sh /data/local/tmp/agent.sh
adb shell chmod 755 /data/local/tmp/agent.sh
adb shell "setsid /data/local/tmp/agent.sh </dev/null >/dev/null 2>&1 &"
```

然后等 1~2 分钟，看日志：

```bash
adb shell "tail -20 /data/local/tmp/agent.log"     # 如果 adb 还活着
```

## 阶段 2：接管

```bash
# 网络侧（如果切了 tcpip）
adb connect <设备IP>:5555

# 或者 USB 已经带 adb 了
adb devices
```

确认能执行命令：

```bash
adb -s <target> shell echo OK
adb -s <target> shell settings get global adb_enabled   # 1 才算焊住
```

---

## 阶段 3：把设备变成"可用状态"

```bash
# 基础三件套
adb shell settings put global adb_enabled 1
adb shell settings put global device_provisioned 1
adb shell settings put secure user_setup_complete 1

# 允许装第三方应用（部分 ROM 需要）
adb shell settings put secure install_non_market_apps 1
adb shell settings put global package_verifier_enable 0
adb shell settings put global verifier_verify_adb_installs 0

# 绕过激活向导（如果是定制机）
adb shell pm hide <setupwizard 包名>     # 用 pm hide 不用 pm disable
```

### 找 setupwizard 的包名

```bash
adb shell pm list packages | grep -iE "setup|provision|wizard|activation"
```

常见形式：`com.android.setupwizard` / `com.xxx.setupwazard` / `com.xxx.activation`。

---

## 阶段 4：持久化（可选但强烈建议）

装一个带 `BOOT_COMPLETED` 的 App，让它每次开机重新焊一次。

```bash
adb install -r bootfix.apk
adb shell pm grant <包名> android.permission.WRITE_SECURE_SETTINGS
```

`WRITE_SECURE_SETTINGS` 是 `signature|privileged|development`，
shell 可以通过 `pm grant` 授予，而且**重启不丢**。

细节见 [03-持久化](03-持久化.md)。

---

## 阶段 5：验证

别只看"现在能用"，要测重启：

```bash
for i in 1 2 3; do
  echo "--- 第 $i 次重启 ---"
  adb reboot
  sleep 70
  adb devices
  adb shell getprop sys.usb.config
  adb shell settings get global adb_enabled
done
```

三次都过 = 真的稳了。

## 常见分支怎么处理

| 情况 | 处理 |
|---|---|
| 窗口内 `settings` 一直失败 | 改用设备侧代理脚本（阶段 1.3） |
| `adb tcpip` 后连不上 IP | WiFi 没起来 / IP 不知道 → `adb shell ip addr` 或看路由器后台 |
| 重启后又回到 9002 | 正常，装 BootReceiver 或接受每次重抓 |
| 装了 App 但开机不启动 | 检查是否被 ROM 的省电策略干掉，或改成前台服务 |
| `pm hide` 后系统进不去 | `pm unhide <包名>` 救回来 |
| 设备没有 WiFi | 只能靠 USB，那就要保证 `adb_enabled` 每次开机都焊上 |

## 交付清单（做完这些才算完成）

- [ ] `adb devices` 能看到设备（USB 或 WiFi 至少一条）
- [ ] `adb shell settings get global adb_enabled` = 1
- [ ] 能装第三方 APK
- [ ] 激活向导已绕过（如果原来是卡在激活页）
- [ ] 重启后至少能自动恢复一条通道（或已接受手动重抓）
- [ ] 把设备型号、`ro.build.fingerprint`、成功的步骤记下来

最后一条很重要：**同一型号的另一台设备，流程几乎一模一样。**
记下来就是资产。
